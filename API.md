# Local API v1

Base URL: `http://<device-ip>`. HTTP Basic user `admin`; індивідуальний пароль
на OLED/через USB `access`. Усі відповіді — JSON, крім HTML, CSV й потоку OTA.
Не відкривайте цей локальний HTTP API у публічний інтернет.

Усі POST вимагають `X-CO2-Request: 1`. JSON body — object, максимум 8192 байти.
CORS/preflight не надаються. Помилки повертають `{"error":"description"}`
із 400/403/409/413/507 відповідно до причини; неправильна авторизація — 401.

| Метод | Шлях | Результат |
| --- | --- | --- |
| GET | `/` | Вебпанель (без зовнішніх assets) |
| GET | `/api/status` | Покази, `fresh`, статуси, діагностика, код HomeKit |
| GET | `/api/settings` | Налаштування без паролів і `_revision` |
| POST | `/api/settings` | Атомарний patch налаштувань |
| GET | `/api/history` | Масив хвилинних записів від старих до нових |
| GET | `/api/history.csv` | Завантаження CSV |
| GET | `/api/backup` | JSON налаштувань без паролів та revision |
| POST | `/api/action` | Команда з таблиці нижче |
| POST | `/api/update` | Multipart upload application `.bin` |

## Settings

Для POST `/api/settings` також потрібен `X-CO2-Revision` зі значенням `_revision`
останнього GET `/api/settings`. Якщо налаштування змінив інший клієнт або
HomeKit, запит відхиляється з 409. Оновіть форму з поточними параметрами перед
новим редагуванням. Успішна відповідь: `{"ok":true,"reboot":false,"revision":...}`.
Не надсилайте `_revision` в JSON body.

Приклад body:

```json
{"led_day":160,"led_night":1,"oled_sleep":true}
```

Назви та поточні значення всіх полів дивіться в GET `/api/settings`.
`schema=1`. Невідомі поля, null, неправильні типи, масиви неправильної форми
та взаємно несумісні значення відхиляються без часткового застосування.
`colors` — 5 масивів RGB; `gains` — 3 числа; `thresholds` — 4 зростаючі межі.

Паролі: відсутній ключ зберігає наявний пароль, явний `""` очищає його.
`wifi_password` допускає 8..63 символи або порожній рядок. Паролі ніколи
не повертаються через GET settings/backup. Backup можна надіслати як patch,
додавши актуальний revision header.

Зміна Wi-Fi/HomeKit/MQTT/timezone перезапускає пристрій через 1.5 с після
відповіді. Зміна sensor override/offset/ASC/altitude/pressure/eco перезапускає
вимірювання. Інші зміни застосовуються одразу. Під час калібрування/оптичного
тесту/обслуговування SCD40 налаштування блокуються кодом 409.

## Status

`co2`, `temperature`, `humidity` — `null`, якщо `fresh=false`.
`slope` — ppm/min або `null` без достатніх свіжих даних.
`epoch=0` означає, що мережевий час не встановлено.
`config_revision` — поточна версія налаштувань.
`night_stats.seconds` — тільки спостережуваний час зі свіжими показами;
`average=null`, якщо даних немає. Стан sensor/optical/calibration містить
результат виконання, а не лише факт прийняття команди.

Код HomeKit доступний лише після HTTP-авторизації. Прямі MQTT/HomeKit
сполучення не використовують адміністративний пароль HTTP.

## History

Кожний JSON запис:

```text
[epoch_seconds, uptime_minute, co2_ppm, temperature_c, humidity_percent, night]
```

Прогалина має `null` у трьох полях вимірювань. `uptime_minute` придатний
для записів без синхронізації часу в межах одного старту; після відновлення
архіву використовуйте epoch. Максимум 1440 записів. Для графіка важливо
не з’єднувати через прогалини та не трактувати їх як нульове CO₂.

## Actions

Body: `{"action":"name", ...}`. HTTP 200 означає прийняття; довгі процедури
потрібно відстежувати через `/api/status`.

| action | Додаткові поля | Поведінка |
| --- | --- | --- |
| `screen` | `page`: 0..4 | Показати сторінку OLED на 60 с |
| `brightness_preview` | `target`: `led`/`oled`, `value`: 0..255 | Preview на 10 с, без запису NVS |
| `preview` | `color`: 0..4 | Preview збереженого кольору на 10 с |
| `vent_start` | — | Почати сесію за свіжого вимірювання |
| `vent_stop` | — | Завершити сесію |
| `cal_dark` | — | 5 с вибірок темної точки |
| `cal_bright` | — | 5 с вибірок світлої точки |
| `cal_apply` | — | Перевірити розмах/шум і зберегти калібрування |
| `optical_test` | — | 21 с тест власного світла |
| `self_test` | — | Самотест SCD40 з перевіркою відповіді |
| `recalibrate` | `reference`: 400..2000, `confirm`: `REFERENCE` | FRC за еталоном після 3 хв безперервного режиму |
| `homekit_pair` | — | Показати дані сполучення; потрібен увімкнений HomeKit |
| `homekit_reset` | `confirm`: `UNPAIR` | Видалити сполучення HomeKit |
| `wifi_reset` | `confirm`: `RESET WIFI` | Очистити Wi-Fi та перезапустити |
| `archive_format` | `confirm`: `FORMAT ARCHIVE` | Стерти/форматувати лише файловий архів |
| `reboot` | — | Перезапустити |

При активній довгій процедурі інші actions відхиляються з 409. Жести не
викликають калібрування, скидання чи зміну Wi-Fi.

## OTA

`POST /api/update`, multipart/form-data, один файл application `.bin`.
Потрібні HTTP auth і `X-CO2-Request: 1`. Сервер перевіряє сімейство прошивки
маркером `CO2_MONITOR_API_V1`, валідність ESP image і цільовий чип.
Маркер не є криптографічною автентифікацією прошивки.
Порожнє, обірване чи відхилене завантаження не повертає успішне оновлення.
Після прийняття — автоматичний reboot та boot health check.

## Додано у 4.1

`wifi_tx_dbm`: максимальна потужність передавача 8.5–19.5 dBm, початково 13.
Зміна налаштування застосовується без перезапуску. Драйвер може квантувати
заданий рівень. `/api/status` повертає фактичний `wifi_tx_dbm` та `wifi_rssi`
(0, коли немає station-з'єднання). RSSI вимірюється в dBm.

## Діагностика 4.1.1

`http_aborted_responses` рахує незавершені HTTP-відповіді з часу старту.
`previous_network_stage` зберігає RTC-маркер перед попереднім програмним
перезапуском: 0 загальна логіка, 1 HomeKit, 2 HTTP, 3 MQTT, 4 архів, 5 setup.
Для інтерпретації використовуйте разом з `reset_reason`; після втрати
живлення попередній маркер не гарантований.
