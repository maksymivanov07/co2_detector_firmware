# CO₂ Monitor 4.1

Прошивка автономного CO₂-монітора **без фізичних кнопок**: ESP32, SCD40,
TEMT6000, KY-016 зі спільним катодом та OLED SSD1306 128×64.
Уся логіка — у `CO_2_Detectior_v3.ino`, статична вебпанель — у `web_ui.h`.
Нативний застосунок для телефона не потрібен; вебпанель працює локально.

## Що реалізовано

- Вебпанель українською для телефона та комп’ютера: покази, графіки, налаштування,
  калібрування, діагностика, резервна копія JSON, CSV та OTA.
- Wi-Fi AP для першого налаштування і відновлення доступу; окремий випадковий
  пароль кожного пристрою, адреса та пароль на OLED; резервні команди USB.
- Apple Home через HomeSpan: CO₂, перевищення порога, температура, вологість,
  перемикач LED. Код сполучення на OLED і вебпанелі; скидання через веб/USB.
- MQTT з Home Assistant discovery, retained state, availability та Last Will.
- 1440 хвилинних записів історії з явними прогалинами, часовими мітками після NTP,
  графіками години/доби й опціональним пакетним архівом flash.
- Тренд за останніми хвилинами, витримка попередження, підозріло низькі покази,
  підсумок ночі та сесія провітрювання з цільовим CO₂.
- Плавна адаптація яскравості, різна швидкість приглушення/підвищення,
  налаштовувана крива, gains та палітра, гістерезис кольорів, нічне гасіння,
  тимчасовий перегляд яскравості й кольорів, необов’язковий денний імпульс.
- Калібрування TEMT6000 за двома точками з оцінкою шуму; тест впливу власного
  LED/OLED; експериментальний жест прикривання/відкривання.
- SCD40: автоматичне відновлення, перевірка свіжості, режими 5/30 с,
  temperature offset, висота/тиск, ASC, самоперевірка та FRC за відомим еталоном.
- OLED: основний екран, два графіки, підсумок/провітрювання, сторінка доступу;
  пробудження, зміщення статичних елементів, передавання тільки змінених рядів.
- Налаштування в NVS: атомарна валідація перед застосуванням, контроль версії
  для захисту від перезапису застарілою сторінкою, запис лише після змін.
- Watchdog і перевірка працездатності нової OTA-версії з відкатом завантажувачем.

## Плата та піни

| Компонент | GPIO |
| --- | --- |
| SCD40 SDA / SCL | 8 / 9, адреса 0x62, 100 кГц |
| SSD1306 SDA / SCL | 4 / 3, програмний I2C |
| KY-016 R / G / B | 20 / 5 / 6 |
| TEMT6000 analog | 2, 12-бітний ADC |

Цільова плата: **ESP32-C3 Super Mini**, підтверджена користувачем.
USB-порт виявлено як ESP32 Family Device на `/dev/cu.usbmodem14201`.
Профіль використовує ESP32C3 Dev Module та схему розділів для flash 4 МБ.
USB CDC увімкнено, щоб Serial не використовував UART RX на GPIO20,
зайнятому червоним LED. USB C3 використовує GPIO18/19.

- GPIO2 — номер GPIO, а не «ADC2». Для C3/S3 цей пін належить ADC1.
- Калібрування світла `2219/2224` збережене зі старої збірки. Діапазон дуже
  вузький, тому перед використанням плавної адаптації пройдіть майстер калібрування.

## Залежності та збірка

Перевіряється з Arduino-ESP32 **3.3.0** та такими бібліотеками:

| Бібліотека | Версія |
| --- | --- |
| HomeSpan | 2.1.8 |
| ArduinoJson | 7.4.2 |
| PubSubClient | 2.8 |
| Sensirion I2C SCD4x | 1.1.0 |
| Sensirion Core | 0.7.1 |
| U8g2 | 2.35.30 |

```sh
arduino-cli lib install 'HomeSpan@2.1.8' 'ArduinoJson@7.4.2' 'PubSubClient@2.8'
tools/build.sh c3
```

`tools/build.sh` використовує CLI з PATH або bundled CLI Arduino IDE для macOS.
Можна перевизначити шлях змінною `ARDUINO_CLI`.
В Arduino IDE потрібна **Partition Scheme: Minimal SPIFFS (1.9MB APP with OTA)**.
Стандартного розділу 1.3 МБ для цієї версії недостатньо.

Результати з’являються у `build/esp32c3/` (ігноруються git).
Для веб-OTA потрібен **`CO_2_Detectior_v3.ino.bin`**, не bootloader, partitions
або merged image. Перший перехід зі старої схеми розділів виконується через USB.

Приклад завантаження для **ESP32-C3 Super Mini**, з фактичним портом:

```sh
arduino-cli upload --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc,PartitionScheme=min_spiffs \
  -p /dev/cu.usbmodemXXXX --input-dir build/esp32c3 .
```

## Перший запуск — без кнопок

1. Підключіть живлення. OLED показує `CO2-Monitor-xxxxxx`, IP, логін `admin`
   та випадковий 12-символьний пароль. Цей пароль також захищає setup Wi-Fi.
2. Підключіть телефон до цієї мережі. Відсутність інтернету в ній очікувана.
3. Відкрийте **http://192.168.4.1** у звичайному браузері та введіть дані з OLED.
4. У «Підключення» вкажіть домашню мережу 2.4 GHz і її пароль. Збережіть.
5. Після перезапуску підключіть телефон назад до домашньої мережі та відкрийте
   IP з OLED. Також доступне ім’я `http://co2-xxxxxx.local`, якщо працює mDNS.

Порожнє поле пароля у формі означає **залишити пароль незмінним**.
На рівні API явний порожній рядок очищає його. При переході на відкриту мережу
можна спочатку скинути Wi-Fi через веб/USB.

Якщо з’єднання не встановлено або втрачено на 60 с, повертається setup AP.
Він вимикається після стабільного підключення, коли до нього вже не підключений
телефон. Звичайне вимірювання не залежить від інтернету чи домашньої мережі.

При вимкненні Wi-Fi в налаштуваннях після кожного старту є 60-секундне вікно
setup AP. Воно залишається відкритим, поки до нього підключений телефон;
після цього радіо вимикається. USB-команда `access` знову відкриває доступ.

Сторінка OLED із паролем показується 60 с при старті/відновленні мережі.
Щоб повторно її побачити, виберіть її у вебпанелі, введіть `access` через USB
або перезапустіть живлення. Жест не виконує жодної адміністративної дії.

## Apple Home

Після налаштування Wi-Fi й увімкнення HomeKit у вебпанелі:

1. У застосунку «Дім» оберіть додавання аксесуара → інші варіанти → CO2 Monitor.
2. Введіть код `xxx-xx-xxx` із вебпанелі або OLED.
3. Додайте його до потрібної кімнати. Для актуальної HomeSpan-конфігурації
   потрібен домашній центр HomePod або Apple TV.

HomeKit працює на TCP 1201, вебпанель — на 80. Фізичний control/status GPIO
HomeSpan не призначається, тому бібліотека не забирає піни датчиків/LED.
HomeSpan є DIY-реалізацією, не сертифікованим Apple аксесуаром.

Числа оновлюються лише за валідного вимірювання. При втраті сенсора
публікуються `StatusFault=1` і `StatusActive=false`. HomeKit не має `null`
для цих числових характеристик; деякі клієнти Apple залишають старе число
й не показують fault. Вебпанель у такій ситуації відображає прочерки.
Графіки, калібрування й довільні пороги доступні у вебпанелі.

Скидання HomeKit через веб/USB видаляє сполучення, але залишає той самий код.
Після цього видаліть старий аксесуар у «Домі» та додайте його знову.

## Вимірювання й аналітика

- Звичайний режим: нові вимірювання близько разу на 5 с, timeout 15 с.
  Економний: раз на 30 с, timeout 90 с. Це економія сенсора; deep sleep ESP32
  не використовується, щоб не порушувати PWM, веб і HomeKit.
- Три невдалі перевірки/читання до успішного вимірювання запускають відновлення.
  Нові спроби — кожні 10 с; таймаут I2C 50 мс. Stop/start і self-test мають
  окремі стани очікування. Самі I2C та мережеві виклики синхронні й обмежені таймаутами.
- Відкидаються CO₂=0 або >40000, NaN, T поза −10..60 °C та RH поза 0..100%.
  Це перевірка значень, а не обіцянка точності в усьому вихідному діапазоні.
- Тренд: лінійна регресія до п’яти останніх хвилин; потрібні щонайменше три
  послідовні валідні точки. Прогалини не з’єднуються.
- Попередження: перевищення налаштованого порога протягом заданого часу;
  зняття — із гістерезисом. За втрати даних таймер підтвердження скидається.
- Підсумок ночі визначається режимом освітлення. Середнє та час понад поріг
  обчислюються лише за наявності свіжих даних; зберігається поточна/остання ніч
  цього запуску. Нічний підсумок і сесія провітрювання не переживають перезапуск.
- Сесію провітрювання запускають із вебпанелі. Вона автоматично завершується
  після 60 с на рівні цілі або нижче; також можна завершити вручну. Максимум — 24 год.
- Стале CO₂ <300 ppm протягом 2 хвилин позначається як привід перевірити калібрування.

## Світло, LED, OLED

ADC: 16 читань у кожній вибірці раз на 100 мс. Фільтр ініціалізується реальним
ADC; приглушення швидше, підвищення повільніше. Перехід режиму вимагає 5 с
підтвердження за порогами 0.30/0.70. У нейтральному діапазоні таймер скидається.

Палітра за замовчуванням: `<300` світло-блакитний; `300..600` блакитний;
`601..1000` фіолетовий; `1001..1500` помаранчевий; `>1500` червоний.
Гістерезис за замовчуванням 25 ppm утримує попередній колір біля межі.

PWM 5 кГц/12 біт, gains 160/180/255, день/ніч 200/1, OLED 200/60.
Нульова LED-яскравість — справді нульовий PWM. Повзунки мають тимчасовий
10-секундний preview; значення записуються в NVS лише кнопкою збереження.
Імпульс попередження діє лише вдень і не перевищує налаштовану яскравість.

Майстер світла: по 5 с для темної та світлої точки; мінімальний прийнятний
розмах — max(10, 3 × сума стандартних відхилень). За сильного шуму або малого
розмаху застосування відхиляється. Отримані апаратні значення варто також
зафіксувати в константах/документації своєї збірки.

Оптичний тест триває 21 с: усе вимкнено → R → G → B → OLED → разом → вимкнено.
Перші 500 мс кожного етапу відкидаються. Навколишнє світло має залишатися сталим.
Тест показує різницю ADC; він не може автоматично відокремити зміну кімнатного
освітлення від самозасвічування. За помітного впливу потрібна перегородка/перерозводка корпусу.

Жест — прикриття на 0.3..2 с і відкриття при денному освітленні, за розмаху ADC
щонайменше 20. Він тільки перемикає сторінки 0..3 на 60 с; у темряві не працює.
Сторінка доступу викликається вебом/USB/стартом, не жестом.

## SCD40: калібрування

За замовчуванням `sensor_override=false`: зчитуються налаштування самого сенсора.
Увімкніть override, щоб застосовувати offset, висоту, ASC та ручний поточний тиск
зі збережених параметрів ESP32. `pressure_pa=0` означає компенсацію за висотою.
Зміни цих параметрів перезапускають вимірювання. Регулярного запису EEPROM
SCD40 немає — параметри застосовуються в RAM при кожному старті.

При вимкненні override вже застосовані RAM-параметри сенсора залишаються до
повного вимкнення живлення SCD40; заводське скидання автоматично не виконується.

FRC потребує відомого еталона 400..2000 ppm, щонайменше 3 хвилин безперервної
роботи та явного підтвердження. Самотест і FRC перевіряють CRC відповіді й показують
помилку замість успіху при збої. Остаточну точність підтверджують еталоном на стенді.

## Історія та час

Без мережі записується монотонний час від старту. Після NTP точки поточного
запуску отримують UTC epoch; локальне відображення в браузері використовує час
телефона. POSIX timezone задається для системного часу (типово Europe/Kyiv правила).

Архів вимкнений за замовчуванням. Для ввімкнення може знадобитися явне
форматування файлової системи в розділі «Система». Прошивка **не форматує flash
автоматично**. Знімки пишуться раз на 15 хв у два черговані файли з CRC.
Після синхронізації часу відновлюються тільки останні 24 год; перерви живлення
залишаються прогалинами. При аварійному вимкненні може втратитися до 15 хв записів.

## MQTT

Вкажіть локальний брокер, порт, користувача/пароль та увімкніть MQTT.
Транспорт — MQTT 3.1.1 TCP, без TLS; не призначений для відкритого інтернету.
Підключення обмежене таймаутами та повторюється раз на 30 с. Discovery retained,
тому Home Assistant може отримати його після свого перезапуску.

- `co2/<device_id>/state`: JSON `fresh`, `co2`, `temperature`, `humidity`, `alarm`, `epoch`.
- `co2/<device_id>/availability`: `online` тільки за свіжих показів, інакше `offline`.
- `homeassistant/sensor/<device_id>/<co2|temperature|humidity>/config`: discovery.

MQTT — канал телеметрії. Керування і калібрування виконуються через захищений HTTP API.

## OTA та доступ

Вебпанель/API захищені HTTP Basic (`admin` + індивідуальний пароль із OLED).
Це HTTP у локальній довіреній мережі, не HTTPS; порт 80 не потрібно відкривати в інтернет.
Запити на зміни додатково вимагають `X-CO2-Request: 1`, CORS не надається.
Backup і читання налаштувань не повертають збережені паролі Wi-Fi/MQTT.

OTA перевіряє ESP application image, відповідність чипу і наявність маркера
цього сімейства прошивки. Маркер захищає від випадкового завантаження іншого
скетча, **не є криптографічним підписом**. Незавершене/пошкоджене завантаження
не обирається для запуску. Під час передавання OTA основний цикл може призупинятися.

Для перевірених профілів core 3.3.0 увімкнений bootloader rollback. Підтвердження
версії відкладається до 60 с роботи, свіжого вимірювання, доступної NVS та успішного
підключення всіх PWM-каналів. Без успіху за 180 с pending-версія відхиляється;
завантажувач повертає попередній валідний образ, якщо він існує. Watchdog — 10 с.
Це потрібно перевірити реальною парою OTA-оновлень на своїй платі.

## USB / Serial

115200 бод, завершення рядка newline. Команди не відлунюють пароль назад:

```text
status
network
access
wifi SSID|PASSWORD
wifi reset
homekit reset
reboot
```

`access` навмисно показує пароль у локальному Serial для відновлення доступу.

## Перевірки

```sh
python3 tests/run.py
# Якщо бібліотека ArduinoJson встановлена в іншому місці:
ARDUINOJSON_DIR=/path/to/ArduinoJson/src python3 tests/run.py

# Лише демонстраційна вебпанель, без емуляції плати:
CO2_PREVIEW_SETTINGS=/tmp/co2-defaults.json python3 tests/run.py
python3 tests/browser_preview.py
```

Host-тести компілюють **реальний скетч** зі спрощеними апаратними заглушками,
реальною ArduinoJson та AddressSanitizer/UndefinedBehaviorSanitizer. Перевіряють
стани сенсора, eco timeout, помилки/CRC, гістерезис, нічний PWM, жести, історію,
налаштування, попередження, ніч, провітрювання, калібрування та OLED sleep.
Мережевий стек/HomeKit/OTA не емулюються цими тестами.

Деталі HTTP — `API.md`, результати перевірок — `REVIEW.md`, стендова процедура —
`HARDWARE_TEST.md`, відповідність повному обсягу — `FEATURE_PLAN.md`.

## Перевірка радіо Super Mini

Під час першого стендового запуску SoftAP повертав успіх, але мережа була
невидимою для iPhone та сканера Mac. Для наступної апаратної перевірки
потужність TX обмежено 8.5 dBm; без домашнього SSID запускається AP-only.
`network` через USB показує фактичні mode/channel/TX/IP/client count.
Результат повторного тесту див. HARDWARE_TEST.md; це не гарантія для всіх
ревізій Super Mini. Аналогічний режим документований для

## Головний OLED-екран 4.1

CO2 займає ліву частину: шрифт 42 для трьох цифр, 32 для чотирьох,
24 для п'яти. Праворуч цілі градуси та вологість. Температура на OLED
відкидає дробову частину до нуля: 25.8 → 25, -2.8 → -2; точні значення
зберігаються у вебпанелі, історії та HomeKit.

Сонце/місяць показують профіль яскравості. Wi-Fi з будиночком означає
підключення до домашньої мережі, з телефоном — setup AP, з пісочним
годинником — очікування мережі; перекреслений — Wi-Fi вимкнено.
Ці іконки не підтверджують доступність контролера Apple Home.
Нижній рядок: CO2 trend та RISING / FALLING / STEADY / WAIT.
Попередження VENTILATE чи CHECK CO2 замінюють підпис тренду.

Параметр `wifi_tx_dbm` (8.5–19.5, тип float) задає максимальну потужність
передавача; початкове значення 13 dBm. Змінюється у вебпанелі без reboot.
Драйвер може квантувати потужність до підтримуваного рівня; фактичний рівень
та RSSI домашньої мережі доступні в /api/status. Більша потужність не гарантує
кращого зв'язку. Перевіряйте у тому самому місці з тим самим живленням.

## HTTP на слабкому зв'язку, 4.1.1

Відправлення відповіді обмежено 2.5 секунди загалом та 500 мс без прогресу;
невдала передача закриває клієнта, а не вимикає watchdog. Історія передається
з відомою довжиною. При обриві браузер повторює запит. Це не виправляє
саме радіопокриття й не гарантує відсутність блокування в інших підсистемах.
Додатковий транспортний тест: `python3 tests/network_write.py`.
