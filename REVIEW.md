# Перевірка початкової прошивки

Перевірено початковий коміт `5d89d01` гілки
`refactoring-and-fix-lamp-in-night-mode`. GitHub CLI не знайшов PR для гілки;
перелік PR репозиторію з `--state all` також порожній. Тому це огляд
коду гілки, а не конкретного PR.

Виправлено під час переписування:

- **Високий пріоритет:** результати запуску/зупинки SCD40 і помилки читання
  ігнорувалися; відновлення не було. Після втрати сенсора старе значення
  могло необмежено залишатися на екрані та керувати LED.
- **Середній:** до першого валідного вимірювання показувалося 0 ppm і
  вмикався колір діапазону <300. Тепер відображається очікування.
- **Середній:** два послідовні округлення 8-бітного PWM з примусовим
  мінімумом 1 вирівнювали різні ненульові канали вночі. Тепер використано
  12 біт й одне округлення без примусового мінімуму.
- **Середній:** фільтр ADC починався з нуля, далеко від калібрування
  2219..2224, а стартова яскравість була денною незалежно від освітлення.
- **Середній:** заголовок день/ніч перемальовувався тільки при зміні
  числових показів сенсора.
- **Середній:** діапазон 601..1000 був зеленим всупереч AGENTS.md.
  Відновлено фіолетовий.
- **Низький:** готовність SCD40 опитувалася приблизно 20 разів/с при
  періоді вимірювання близько 5 с, контраст OLED повторно задавався
  кожні 500 мс. Частоту зайвих операцій зменшено.

Окремо перевірено: встановлена бібліотека Sensirion 1.1.0 сама виконує
`delay(500)` у `stopPeriodicMeasurement()`. Тому відсутність явної паузи
між stop/start у початковому коді **не була помилкою**. Новий код надсилає
документовану команду stop 0x3f86 через Wire й витримує паузу станом,
щоб дисплей та освітлення могли продовжувати оновлюватися.

Обмеження: фізичну плату не визначено й не підключено. Калібрування
освітленості та вигляд нічного RGB потребують стендової перевірки.

## Початкова валідація базового переписування

- Компіляція `esp32:esp32:esp32s3`, core 3.3.0, `--warnings all`: успішна.
  Flash: 391559 байт (29%); глобальна RAM: 23792 байт (7%).
  Компілятор видає попередження в U8g2, Sensirion Core та ESP32 core.
- `python3 tests/run.py`: PASS для всіх сценаріїв.
- `git diff --check`: без помилок.
- `arduino-cli board list`: лише Bluetooth-порти, плата не виявлена;
  прошивання та апаратний смок-тест не виконані.

Перевірені первинні джерела:
- [Espressif LEDC API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html)
- [Sensirion SCD4x driver](https://github.com/Sensirion/embedded-i2c-scd4x/blob/master/scd4x_i2c.c)
- Локальна реалізація `SensirionI2cScd4x::stopPeriodicMeasurement()` бібліотеки 1.1.0.

## Розширення 4.0

Реалізовано локальну вебпанель, Wi-Fi setup/recovery без кнопок, HomeKit,
MQTT discovery, налаштування NVS, добову історію/CSV/архів, аналітику,
калібрування та діагностику датчиків, адаптивну індикацію й веб-OTA.
Повний перелік — у FEATURE_PLAN.md; API — у API.md.

Фінальні host-тести виконують фактичний код скетчу з апаратними заглушками
та ArduinoJson 7.4.2, з AddressSanitizer/UndefinedBehaviorSanitizer: PASS.
Мережевий код, NVS, файловий архів і OTA не емулюються цими тестами.
JavaScript вебпанелі проходить `node --check`. У браузері перевірено
демонстраційні покази, графік з прогалинами, налаштування, провітрювання,
калібрування та адаптацію до ширини телефона; це fixture, а не фізична ESP32.

Паралельна компіляція C3/S3 виявила спільний стандартний кеш Arduino CLI:
лінкер отримував об'єкти іншої архітектури. tools/build.sh тепер задає
окремий --build-path для кожного чипа.

HomeKit pairing, MQTT з брокером, реальне OTA/rollback, архів після втрати
живлення, струм споживання та оптичне калібрування потребують плати.
Стендовий перелік перевірок — HARDWARE_TEST.md. Прошивання не виконувалося.

Фінальна збірка для підтвердженої користувачем **ESP32-C3 Super Mini**:
`tools/build.sh c3` — PASS. Flash 1759844 / 1966080 байт (89%),
статична RAM 78464 / 327680 байт (23%). Маркер сімейства в образі перевірено.
Профіль S3 вилучено після уточнення апаратної моделі. Фінальний образ 4.1.2
записано на ESP32-C3 Super Mini та перевірено через USB і мережу.

4.1.1: виявлено ризик watchdog у блокувальному HTTP send, реалізовано
обмежений неблокувальний запис та Content-Length історії. Тест реального
класу на socketpair PASS. C3/core 3.3.11 compile PASS (1779275 bytes flash,
80144 bytes static RAM). Апаратний запис 4.1.2 підтверджено; повторний тест
на потрібному місці показав стабільний Wi-Fi та HTTP без нових перезапусків.
